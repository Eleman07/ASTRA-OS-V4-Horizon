# Requirements and Verification

Each requirement needs an observable result, a unit/tolerance when applicable, a rationale and a verification method. Separate a desired capability from evidence that it has been achieved.

Use the [[Astra Command Center/90 Templates/Verification Matrix|Verification Matrix]] for a particular project. For changed requirements, record which tests and decisions become stale in [[Astra Command Center/16 Verification Debt|Verification Debt]].

## Numerical evidence checklist

- Exact input values and units, with source locations.
- Reference frames, epoch and sign conventions.
- Deterministic calculation or actual simulation/test command.
- Expected result and tolerance chosen before seeing the result.
- Actual result, uncertainty and residuals; retain failed runs.
- Reviewer and acceptance date.
